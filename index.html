D141 Site Setup

Prototype hub

Mockup only - fake data - Proposal unless owner-stated

Capturing D141 camera site data directly in Salesforce (CMCS), extending the existing Site object and its child records with validation at the point of entry, instead of an Excel form that is re-keyed. The spreadsheet layout does not have to be copied: the outcome is validated, complete site details feeding CMCS. Each variation below is a separate, Lightning-styled prototype of the same data model (five record types: FDSC, RLSC, BPES, ASC, ODES).

2-minute walkthrough

What this is

Technical Project Managers fill an Excel D141 for every camera site, and another business unit re-keys it into CMCS. These prototypes show how the same data could be captured directly in Salesforce, with validation at the point of entry. It is a mockup with fake data for the Salesforce build team; nothing is built in Salesforce.

Who it is for

The program owner (to decide), Technical Project Managers, unit managers, camera networks engineers, CMCS data stewards, and the Salesforce delivery team.

How to read it

Proposal means the owner did not state it. ? marks an open question at the exact spot it matters. The Help button (top right) has a map, legend and glossary.

Four things to try

  1. Create a site: pick a record type and watch the layout change.
  2. Trigger a validation error: click Edit, type 192.0.2.300 in IP Address (Camera) and leave the field.
  3. Update several sites at once: select rows, use the bulk action bar, mark a stage complete.
  4. Open a question in context: click the blue ? beside Data Block Approval Date.

Two-minute walkthrough

  1. Read the three variations below and pick one that fits the job.
  2. Open it; the grey bar under the menu shows where you are and has a Back to hub link.
  3. Click the Path stages, edit a field, press Mark Status as Complete.
  4. Open Stories for this screen (bottom bar) to see which stories and acceptance criteria govern it.
  5. Check Journey for the end-to-end picture and Questions for what is still undecided.

Capture variations

1. Guided single-site record page

Site list, New Site with record type picker, then a Lightning record page with a Path across the lifecycle, stage-gated sections, inline edit and attachments.

Use it for
Entering or maintaining one site, following it through each lifecycle stage.
Prefer when
A TPM is working a single site over weeks and needs the stage gates and attachments in one place.

2. Bulk grid entry

Editable grid of Sites with per-row validation, child-record readiness, and a bulk action bar (Commission, Decommission with the existing Camera removed / Camera upgraded statuses, Refurbish, mark stage complete, set value).

Use it for
Entering or changing many sites at once (a batch of installs, a decommission run, a refurbishment programme).
Prefer when
The same few fields change across many sites and speed matters more than per-site guidance.

3. Guided screen flow

Step-by-step wizard (Screen Flow style) that creates the Site and its Lanes, Camera Program, Enforcement Devices and Certificates, one concern per screen with validation before Next.

Use it for
First-time creation of a site by someone who does not know the data model.
Prefer when
Fewer mistakes matter more than speed; new or occasional users.
